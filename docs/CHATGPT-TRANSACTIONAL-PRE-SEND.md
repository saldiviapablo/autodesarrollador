# Transactional ChatGPT preparation

New ledgers use schema 2.0 and persist `RESERVED → PREPARED → DELIVERY_INTENT → SENT_CONFIRMED → COMPLETED`. PREPARED is fsynced only after source/DOM SHA equality and contains the turn baseline and conversation URL. The physical delivery function requires PREPARED. An interrupted unconfirmed zero-attempt PREPARED record becomes PRE_SEND_INTERRUPTED; a reserved record can abort without claiming ambiguous delivery. New zero-attempt records cannot become UNKNOWN_DELIVERY. Corrupt metadata fails closed as LEDGER_CORRUPT. Legacy schema 1.0 records are read without migration or rewriting.

Rollback and orphan recovery require a unique matching owner, exact SHA, baseline, conversation, dedicated profile, visible editable composer, no streaming, no intent in ledger/history/trace and no physical send trace. An immediate second inspection and unchanged ledger hash precede a composer-scoped clear; three subsequent observations must remain empty with unchanged turns. A separate fsynced receipt contains only hashes and metadata. Automatic retry of the same ID requires a validated receipt; forged markers do not suffice. Genuine post-intent ambiguity retains no_resend and the explicit human reconciliation route. Confirmed delivery is irreversible and response waiting remains separate.

ATTEMPT5 recovery is explicitly scoped to its known ID/hash in LEGACY_PRE_SEND_RECOVERY. It creates a receipt and preserves the original ledger and trace byte-for-byte. The current root/0/0 empty composer is reused without a New Chat click. Existing conversations allow one navigation attempt, followed by the same empty/owned/unknown draft checks. Unknown or ambiguous owners always deny clearing.

The Unicode probe refuses any preexisting text. The send actuator remains one preselected scoped submit or physical Enter pair, with no cross-method fallback after intent. The bridge reserves a 20s finalization stage for bounded profile checks and rollback; a 60s response budget yields 126s internal and 134s parent budgets, below the unchanged 300s F24 phase limit. F24's 2700s global, restart2 and maxcycles5 limits remain unchanged.

Certification continues from the preserved working tree and receipts under `evidence/f24-transaction-cert-20261014/`. No local model configuration, security policy, approved historical hashes, historical states or 28-gate catalog were weakened. Prior F24 attempts remain historical failures.
